# Security and quality audit - 2026-09-06

Scope: llmp2p v0.2.0 (`dc9874b`). Method: manual review of every trust
boundary (network inputs, filesystem, process, crypto, concurrency, CI),
cross-checked against the automated gates already running in CI (go vet,
race detector, golangci-lint, gitleaks, govulncheck).

Every finding below was verified against the code before being recorded;
rejected observations are listed with the reason they do not hold.

## Verified and fixed

| # | Finding | Severity | Fix |
|---|---------|----------|-----|
| 1 | Manifest file paths were not checked for traversal (`..`, absolute, backslash, control characters): a served manifest could make `VerifyDir` hash files outside the model directory (hash oracle). | Medium | `validateManifestPath` at parse time and before `Create` touches the filesystem (fix(manifest)) |
| 2 | Data race: `writeMetrics` read the live `pullStats` map while job-completion goroutines wrote it under `s.mu`. | Medium | Snapshot under the lock + race test (fix(daemon)) |
| 3 | `POST /api/v1/pulls` decoded an unbounded request body. | Medium | `http.MaxBytesReader`, 64 KiB cap (fix(daemon)) |
| 4 | Pull jobs ran with no deadline: a stalled transfer held the sequential queue forever. | Medium | 2 h job budget on the detached context (fix(daemon)) |
| 5 | `llmp2pd` only handled SIGINT; the documented systemd deploy sends SIGTERM, which killed the daemon without graceful shutdown. | High (ops) | Both signals notified (fix(daemon)) |
| 6 | `llmp2pd` never received the release version (ldflags only targeted the CLI's variable): `--version` and the status endpoint reported 0.0.0. | Medium | Daemon-specific ldflags line (`main.version`) in build, install and dist (fix(build)) |

## Accepted design decisions (not defects)

- **The bootstrap index is unsigned** (ADR-0004): it is the trust anchor,
  equivalent to a package index with PR review. Its compromise is mitigated
  by the manifest sha256 pin, signature sidecars and the final per-file
  sha256 against Hub oids. BEP 44 records (ADR-0008) provide an alternative
  trust root rooted in the user's allowlist.
- **Deterministic DHT salt** (`sha256(model id)`, ADR-0008): the salt is not
  a secret; record addressing is protected by the ed25519 publisher key, and
  determinism is required for clients to derive the target.
- **Model downloads have no size cap**: artifacts are multi-gigabyte by
  design; integrity is enforced by piece hashes and the final per-file
  sha256. Metadata fetches (index 16 MiB, manifest 64 MiB, sidecar 1 MiB)
  are capped.

## Observations rejected during review

- "Response size caps missing on Hub API/downloads": capped where it matters
  (see above); capping model downloads would break real pulls.
- "Redirect attacks on the download client": Go's default policy allows 10
  redirects; the final content is bound by sha256/oid, not by origin.
- "Argument injection via `ollama create` model name": `exec.Command` does
  not use a shell; the name is the operator's own choice on their own
  machine.
- "Non-constant-time sha256/hex comparisons": compared values are public
  digests, not secrets; timing attacks do not apply.
- "Partial files with 0644 leak secrets": they contain model bytes, not
  credentials.
- "Publisher key directory permissions": keys are written 0600 by
  `signing.LoadOrCreate` inside the user's own store; no cross-user concern
  on single-user stores.
- "`--allowed-signers` documentation mismatch": the documented behavior
  (unsigned manifests rejected when the allowlist is set) matches the code.

## Follow-ups

- Fuzz the manifest and DHT record decoders (candidate for a later cycle;
  both parsers are strict and table-tested today).
- Add a pull-job duration metric to `/metrics` (nice-to-have, not security).
